# Week 5 Reflection

One thing I learned from the readings is that Git records changes over time, while GitHub makes it easier to share those changes and collaborate. I now understand why commits should have clear messages: they help me see what changed and why. This is especially useful in analytics, where a project may go through many versions of a dataset, analysis, or report.

My biggest challenge was understanding branches and knowing where to make each change. At first, I was confused about whether `update-bio` already existed and where my README edit would go. I worked through it by checking the Current Branch in GitHub Desktop, making the edit, publishing the branch, and opening and merging a pull request on GitHub.

In future team projects, GitHub could help everyone work on their own branch and review changes before they become part of the main project. Issues could also help us keep track of tasks, while commits and pull requests would show how the work progressed. That would make it easier for the team to stay organized and understand each person's contribution.
